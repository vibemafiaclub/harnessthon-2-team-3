# B-3 후보 생성 — 축 1: 홈의 조직 원리

> 축 정의(`decisions.md` B-1): 수십 건의 진행 중인 조율을 앱이 **무엇을 기준으로 조직해** 보여주는가.
> 양 끝: `행동 큐`(지금 할 일만) ↔ `상태 보드`(단계별 칸) ↔ `캘린더`(시간 축).
> 출처 DP-02, 종속 DP-05(회신 수합 화면의 축).
>
> **이 문서의 경계** — 축 2(편성 주도권)와 축 3(비주얼 무드)은 다루지 않는다. 색·서체·밀도감·정서는 한 줄도 쓰지 않고, 편성 동선(다중선택/자동제안)도 언급하지 않는다. 화면 기술은 전부 **무채색 전제의 구조**다.
>
> **사전 필터**: `PT-02`(가용성 매트릭스)는 최소 폭이 데스크톱이므로 세 후보 어디에도 올리지 않는다 → DP-05 선택지 (c) 전 후보에서 탈락. 세 후보의 DP-05는 (a) 날짜별 리스트 + 참석자 뱃지 / (b) 사람별 리스트 중에서만 갈린다.

# 후보 A (무난) — 단계 보드 리스트

> 한 줄: **홈 = D-day 바 + 상태 6종을 섹션으로 자른 전체 모임 리스트.** 자도메인 컨벤션(진행 단계로 조직)을 리스트 형태로 그대로 따른다.

## 1. 구조 기술

```
[상단 고정] D-day  ·  미배정 12명 ›            ← 1줄, 항상 존재
────────────────────────────────────────
회신 대기  (9)                                ← 섹션 헤더 = 상태 라벨 + 건수
  대학 동기 4인          2일째 무응답   ›
  회사 팀    3인          오늘 21시 마감  ›
  …
후보 발송 전 (5)
  …
확정 (7)
  …
완료 (6)                                      ← 접힘 기본
```

- **섹션 = 상태 1종.** 자도메인 어휘(`refs/axis1-home.md` 컨벤션 2)로 라벨링한다. 항목이 0건인 섹션은 **헤더째 사라진다**(ref-01 규칙).
- **진입 자격**: 없다. **모든 모임이 항상 어딘가에 뜬다.** 이게 이 후보의 정의이자 약점이다 — 20~30줄 전체가 홈에 있다.
- **섹션 정렬**: 상태 기계의 진행 순서 역순(덜 끝난 것이 위). 섹션 내부 정렬은 앱이 고정(마감 임박순), 사용자 설정 없음(ref-03 컨벤션 2).
- **행**: 2줄(72dp). 줄1 = 모임명 + 인원, 줄2 = 이 상태에 머문 시간/원인. 다음 행동은 트레일링 셰브런으로 밀어낸다(ref-04 예산).
- **미배정 처리**: 미배정은 *사람*의 상태라 모임 보드에 자리가 없다. 그래서 **상단 고정 바에 카운트로 외부화**한다. 이 외부화 없이는 D-03 위반으로 후보 자격이 사라진다(아래 4항).

**DP-05 종속** → **(b) 사람별 리스트.** 보드는 "모임이 지금 어느 칸인가"를 축으로 삼으므로, 모임 상세에 들어간 뒤의 자연스러운 다음 축은 그 모임의 **구성원 상태**다. 회신 수합 화면 = 참석자 3~6명이 행이고, 각 행에 응답/미응답 + 고른 날짜. 무응답자가 행 단위로 튄다(`D-04`). 날짜별 집계는 화면 하단 요약 줄로 축약된다.

## 2. 근거 ref — 혼합 흔적

- **ref-05(자도메인)**: 홈 최상단 D-day 고정, 준비 상황을 **단계로 조직**한다는 골격. 단 **진척률 게이지/퍼센트는 버렸다** — "68% 완료"는 다음 행동을 하나도 알려주지 않는다(ref-05 안 가져올 것). 퍼센트 자리에 **섹션별 건수**를 넣은 것이 변형점.
- **ref-01(Linear)**: 섹션 분할 정렬 + **"항목 없으면 섹션 자체가 소멸"**. 다만 Linear는 *긴급도*로 섹션을 자르는데 A는 *상태*로 자른다 — 같은 메커니즘을 다른 키로 돌린 것이다.
- **ref-04(M3)**: 2줄 72dp 상한, 트레일링 셰브런.

1:1 대응이 아닌 근거: ref-05는 "무엇을 조직 축으로 삼는가"만 주고 그 구현(섹션 소멸 규칙·건수 노출)은 ref-01에서, 행 예산은 ref-04에서 왔다.

## 3. PT 인용과 성립 판정

`PT-03`(상태 보드)은 `ux-patterns.md`에서 **TODO 상태**다. 후보로 올리려면 작성 규칙 2에 따라 5필드를 채워야 하므로, 이 후보가 그 초안을 만든다.

> **PT-03 — 상태 보드 (Status Board) [신규 제안]**
> - **푸는 문제**: 다수 항목이 서로 다른 단계에 흩어져 있고, 실패 모드가 행동 누락이 아니라 **조회 실패**(어디 있는지 모름)일 때.
> - **형태**: 상태를 섹션(모바일) 또는 열(데스크톱)로 자르고 모든 항목을 소속 상태 아래 배치. 항목은 상태 사이를 이동한다.
> - **성립 조건**: 상태 종류 **3~7**, 총 항목 수가 한 화면 스크롤 **3화면 이내**(모바일 2줄 행 기준 ≈ **24행**). 최소 폭: **모바일(세로 섹션 형태에 한해)** — 가로 칸(칸반) 형태는 360px에서 한 칸만 보이므로 불가(ref-01 관찰).
> - **무너지는 조건**: 한 섹션이 화면 높이를 넘으면 그 섹션 안에서 다시 "뭐부터"를 사람이 계산해야 한다. 상태가 8종 이상이면 섹션 헤더가 화면의 절반을 먹는다.
> - **대안 패턴**: `PT-01`(행동 촉구가 목적일 때).
> - **근거**: 이식(ref-01·ref-05) + 이 프로젝트의 미실측. **A단계 20/30건 더미 검증 필요.**

**이 프로젝트 숫자 대입**: 상태 6종 ✅ 3~7 범위 안. 총 항목 20~30건 × 72dp = **1440~2160dp** → 844pt 화면 기준 **약 2~3화면**. 상한(24행)에 20~30건이 **걸친다** → **조건부 성립**. 30건 쪽에 가까워지면 불성립. `회신 대기` 섹션 하나가 9~14건이 되는 시점(3개월 전~2주 전 구간의 중반)에 PT-03의 무너지는 조건("한 섹션이 화면 높이 초과")이 **실제로 발동한다.**

## 4. D-01~D-06 위반 검토

| 제약 | 판정 | 근거 |
|---|---|---|
| **D-01** (앱이 다음 행동을 지목) | **⚠️ 부분 위반 — 완화 필수** | 섹션은 *상태*를 알려줄 뿐 *급한 것*을 지목하지 않는다. `회신 대기 (9)` 안에서 오늘 21시 마감과 3일 뒤 마감이 같은 시각적 지위를 갖는다. **완화**: 섹션 내부 정렬을 마감 임박순으로 앱이 고정하고, 줄2에 원인 문구를 의무화한다. 완화해도 사용자는 여전히 **섹션을 훑어 비교**해야 하므로 완전 충족은 아니다 |
| **D-02** (N:M) | ✅ | 모임 단위 리스트라 한 사람이 여러 줄에 등장해도 모순 없음 |
| **D-03** (미배정 수 상시 도달) | **조건부 통과** | 보드 구조상 자리가 없어 상단 고정 바로 외부화. 이 바가 빠지면 **후보 자격 소멸** |
| **D-04** (무응답 = 시간) | ✅ | 줄2가 "2일째 무응답"·"오늘 21시 마감" |
| **D-05** (풀 분리·캘린더 통합) | ✅ 위반 아님 (홈이 막지 않음) | 단 후보일 선택 시 상대편 일정 노출은 **별도 화면**이 전담. 홈은 기여하지 않는다 |
| **D-06** (1:1·양가 동반은 값) | ✅ | 인원수는 줄1의 값일 뿐 화면이 갈라지지 않음 |

→ **후보 자격 있음** (단 상단 고정 바 + 섹션 내 마감순 고정이 조건).

## 5. 깨지는 조건

1. **`회신 대기` 섹션이 10건을 넘는 순간.** 3개월 전~2주 전 중반에 실제로 도달한다(20~30건 중 대기 상태 비중이 가장 크다). 그 순간 홈은 "상태별로 정리된 것"이 아니라 "긴 리스트 앞에 헤더가 붙은 것"이 된다.
2. **12주 내내 화면 골격이 동일하다.** 섹션 5~6개가 계속 있고 괄호 안 숫자만 바뀐다. 주 수회 12주 = 30~60회 반복에서 **변화 감지가 숫자 읽기에 전적으로 의존**한다.
3. **완료가 쌓이는 후반.** 완료 6→25건이 되면 접혀 있어도 섹션 헤더가 스크롤 하단을 차지한다.
4. **급한 모임(2주 전, 마감 단위가 몇 시간)**이 다른 대기 건과 같은 섹션에 섞여 시각적으로 구별되지 않는다.

# 후보 B (추천) — 2층: 행동 큐 위, 다가오는 모임 아래

> 한 줄: **홈 = 얇은 D-day 줄 + 행동 신호가 켜진 모임만 모은 큐(상단) + 확정된 모임의 시간순 목록(하단).** 큐냐 캘린더냐를 고르지 않고 **층으로 쌓았다.**

## 1. 구조 기술

```
D-day 34  ·  미배정 12명 ›                     ← 1줄 고정
════════════════════════════════════════
지금                                          ← 신호 1: 마감 도래
  회사 팀     3인      21시 마감 · 2명 미응답  [확정]
막힘                                          ← 신호 2: 무응답 경과
  대학 동기   4인      3일째 무응답            [독촉]
겹침                                          ← 신호 3: 날짜 충돌
  이모네 · 신부 동창    10/12 같은 날          [조정]
────────────────────────────────────────
다가오는 모임                                  ← 하단: 확정된 것만, 시간순
  10/12 토  이모네        신랑 · 5인
  10/12 토  신부 동창     신부 · 4인
  10/19 토  대학 선배     신랑 · 3인
```

- **큐 진입 자격 = 단일 규칙** (ref-03): **행동 신호 3종 중 하나라도 켜진 모임만** 큐에 뜬다. 신호가 없는 모임은 홈에 **아예 없다** — 상세로 들어가야 보인다. 이것이 A와의 결정적 구조 차이다.
- **큐 섹션 3개**(지금 / 막힘 / 겹침)는 신호 종류와 1:1. 해당 신호가 0건이면 **섹션째 사라진다**(ref-01). 신호가 전부 0이면 큐 영역 자체가 사라지고 하단 목록만 남는다 — 이게 "오늘 할 일 없음"의 표현이다.
- **행 = 1~2줄**, 트레일링에 **동사 버튼 1개**(확정/독촉/조정). ref-04 예산상 다음 행동을 3줄째 텍스트로 넣지 않고 버튼으로 밀어낸다. 화면 하단 1/3 원칙과 어긋나는 상단 버튼은 **파괴적이지 않은 동작만** 배치(`brief.md` 손 상황).
- **하단 = 확정된 모임만** 시간순. 미확정은 여기 없다(큐가 담당). 각 줄에 소유자 표시(`ASSUMP-13`).
- **미배정**: 상단 고정 줄에 상시(D-03). 큐가 비어도 이 줄은 남으므로 "완전히 빈 홈"이 발생하지 않는다.

**DP-05 종속** → **(a) 날짜별 리스트 + 참석자 뱃지.** 큐의 다음 행동이 `[확정]`이고 확정의 단위가 **날짜**이므로, 회신 수합 화면은 결정 단위와 축을 맞춘다. 후보일 3~6개가 행이고 각 행에 응답한 사람 뱃지 + 인원 카운트, **미응답자는 화면 하단에 별도 블록**으로 뺀다(ref-03의 "격자에 자리 없는 것은 격자 밖으로"를 리스트로 옮긴 것). 마감 시계는 화면 상단. 부분 확정 버튼이 정상 경로로 열린다(`D-04`).

## 2. 근거 ref — 혼합 흔적

- **ref-02(Airbnb Today)**: 홈의 2층 구조 자체 + 마감 카운트다운. 단 **카드가 아니라 한 줄로 압축**했다 — 호스트는 1회 수 분, 우리는 수십 초(ref-02 안 가져올 것).
- **ref-01(Linear)**: 큐를 긴급도 섹션으로 자르고 빈 섹션은 소멸. 8섹션 → **3섹션으로 축소**(우리 신호가 3종). 이게 우리 제약에 맞춘 변형.
- **ref-03(Todoist)**: **큐 진입 자격을 단일 조건으로 정의**. "날짜가 있는 것" → "행동 신호가 켜진 것"으로 치환. **미루기는 채택하지 않았다** — 예식일 고정이라 미루기가 곧 누락(ref-03 안 가져올 것).
- **ref-04**: 행 예산, 행동은 트레일링.
- **ref-05**: D-day 고정 위치라는 자도메인 컨벤션만. 진척률은 버림.

세 타도메인 레퍼런스가 각기 다른 부분(층 구조 / 섹션 규칙 / 진입 자격)을 대고, 자도메인은 컨벤션 1개만 댄다. 1:1 대응 아님.

| 행동 신호 출처 **2종 이상** | 3종 (마감·무응답·충돌) | ✅ |
| 최소 폭 **모바일** | 390 설계 / 360 하한. 302px 텍스트 폭에 "모임명 3인 / 21시 마감 · 2명 미응답" 2줄 수용 | ✅ |

→ **성립.** 네 조건 모두 충족한다. 다만 PT-01의 **무너지는 조건 중 하나가 우리 규모에서 실제 위험**이다: *"큐가 항상 비어 있거나 항상 20줄이면 둘 다 실패."* 20~30건 중 회신 대기가 절반이고 그중 무응답 3일 경과가 흔하면(PRD §3-4가 "꼭 있다"고 함) **`막힘` 섹션이 10줄을 넘을 수 있다.** → 완화 장치가 필요: `막힘` 섹션 상한 5줄 + "N건 더 보기"로 접고, 그 이상은 큐가 아니라 별도 뷰로 넘긴다. **이 상한값은 근거 없는 발명이므로 A단계 더미 데이터 검증 대상**(`refs/axis1-home.md` 사각지대 1과 같은 항목).

하단 층은 `PT-03`이 아니라 **단순 마감순 정렬 목록**(PT-01의 대안 패턴 항목)이다. 별도 PT 신설 없음.

## 5. 깨지는 조건

1. **무응답이 드물면(응답률 90%+) 큐가 상시 비고 홈이 하단 목록만 남는다** — 그러면 이 후보는 그냥 "확정 목록"이 되고 층 구조가 낭비다. `core-problem.md §2` 반증 조건 3번과 같은 신호.
2. **`막힘`이 10줄을 넘는 시기.** 위 3항의 5줄 상한이 실측 없는 발명이므로, A단계에서 30건 더미를 넣었을 때 접힘이 정보를 숨기는 쪽으로 작동하면 깨진다.
3. **신호 없는 모임이 홈에서 안 보인다.** "지금 조용한 8건"을 사용자가 확인하고 싶을 때 홈이 답을 못 준다 — 사용자가 조회를 원하면 매번 다른 뷰로 나가야 하고, 그게 잦으면 실패 모드 판정(행동 누락 vs 조회 실패)이 틀렸다는 증거다.
4. **큐 0건 + 확정 0건의 초기 상태.** 앱을 막 시작한 사용자는 홈에 미배정 카운트 한 줄만 본다. "다 처리해서 빔"과 "아직 시작 안 함"의 구분이 필요한데 이 구분의 근거가 소싱에서 안 나왔다(`references.md` 사각지대).

# 후보 C (도전) — 주말 슬롯 스트립

> 한 줄: **홈 = 예식일까지 남은 주말을 세로로 늘어놓은 시간 축이 조직 원리이고, 아직 자리를 못 잡은 모임은 축 밖 별도 패널에 쌓인다.** 희소 자원(주말)의 소진을 1급 정보로 삼는다.

## 1. 구조 기술

```
D-day 34  ·  미배정 12명  ·  자리 없는 모임 7건 ›
════════════════════════════════════════
이번 주말   10/11 토 – 10/12 일
   토  이모네        신랑 5인
   토  신부 동창     신부 4인   ⚠ 같은 날
   일  ―                                   ← 빈 슬롯이 명시적으로 보인다
다음 주말   10/18 – 10/19
   토  대학 선배     신랑 3인
   일  ―
10/25 – 10/26
   ―  ―                                    ← 통째로 빈 주말
…
────────────────────────────────────────
자리를 못 잡은 모임  7                        ← 격자 밖 패널
  회사 팀      21시 마감 · 2명 미응답   [확정]
  대학 동기    3일째 무응답             [독촉]
  … 5건 더
```

- **조직 축 = 남은 주말.** 12주 × 주말이면 행이 12개 그룹, 각 그룹에 토/일 슬롯. **빈 슬롯을 지우지 않고 명시적으로 그린다** — `brief.md` "빈 것이 시각적으로 튀어야 한다"의 시간 축 버전. 남은 자리가 줄어드는 것이 곧 진척 표시다.
- **진입 자격**: **확정된 모임만** 축 위에 올라간다. 확정 전 모임은 시간 축에 놓을 자리가 없으므로 **격자 밖 하단 패널**로 뺀다(ref-03의 overdue 사이드 패널 메커니즘을 세로 모바일로 이식). 패널 안은 마감 임박순, 각 줄에 원인 + 트레일링 동사 버튼.
- **충돌이 구조적으로 보인다.** 같은 날 두 모임이 같은 그룹 안에 나란히 놓이므로 `⚠ 같은 날`이 별도 신호가 아니라 **배치 그 자체**다. 양가 소유자가 같은 행에 붙으므로 D-05의 "합쳐서 한눈에"가 홈에서 성립한다.
- **스크롤 방향이 시간**이다. 위가 가까운 미래, 아래가 예식일. 스크롤 끝이 예식일이라 **끝이 있는 리스트**다(A·B는 끝이 상태·건수로 정해져 무의미).

**DP-05 종속** → **(a) 날짜별 리스트 + 참석자 뱃지.** 홈의 축이 날짜이므로 회신 수합 화면도 날짜 축을 유지해야 홈↔상세 전환에서 축이 꺾이지 않는다. 후보일 3~6개가 행, 각 행에 응답자 뱃지. 여기에 C만의 추가 요소: **각 후보일 행에 "그 날 이미 잡힌 다른 모임"이 함께 표시된다** — 홈이 시간 축이라 이 정보가 자연스럽게 상속되고, `D-05`("후보일을 고르는 순간 상대편 확정 일정이 같은 화면에")를 **홈-상세 일관성으로** 충족한다.

## 2. 근거 ref — 혼합 흔적

- **ref-03(Todoist)**: 결정적으로 **"캘린더 격자에 놓을 자리가 없는 것은 격자 밖 패널로 뺀다"**. Todoist는 사이드 패널(데스크톱)이지만 우리는 세로 하단 패널로 옮겼다 — 이게 모바일 이식 변형점이고, ref-03의 "캘린더는 조건부 성립, 격자 밖 패널이 조건"이라는 관찰을 그대로 실행한 유일한 후보다.
- **ref-02(Airbnb)**: 2층 구조의 **상하를 뒤집었다**. Airbnb는 큐가 위·시간순이 아래인데 C는 시간축이 위·큐가 아래다. 같은 메커니즘의 반전이므로 목업에서 B와 눈으로 즉시 구분된다.
- **ref-01(Linear)**: 하단 패널이 빈 섹션 소멸 규칙을 따른다. 패널이 0건이면 사라지고 시간 축만 남는다.
- **ref-05(자도메인)**: D-day 고정 + **컨벤션 3(예산·비용 홈 노출)을 의도적으로 어긴다.** 자도메인 앱은 홈에 예산을 기대하게 만들지만 우리 job이 아니다(`refs/axis1-home.md` 컨벤션 3이 "의도적으로 어겨야 할 후보"로 지목).
- **버린 것**: ref-05의 카테고리 탭, ref-03의 미루기·사용자 정렬 설정.

## 3. PT 인용과 성립 판정

`ux-patterns.md`에 시간 축 패턴이 없다(`PT-04`가 TODO). 작성 규칙 2에 따라 신설안을 제시한다.

> **PT-04 — 희소 슬롯 스트립 (Scarce Slot Strip) [신규 제안]**
> - **푸는 문제**: 항목이 유한하고 미리 알려진 **슬롯**을 두고 경합하며, 실패 모드가 **충돌 또는 자리 소진**일 때. 조회 대상이 항목이 아니라 **남은 자리**다.
> - **형태**: 슬롯을 시간 순서로 세로 나열하고, 배정된 항목을 슬롯 아래에 붙인다. **빈 슬롯을 지우지 않는다.** 미배정 항목은 스트립 밖 별도 패널에 쌓아 각 줄에 다음 행동을 붙인다.
> - **성립 조건**: 슬롯 총수가 **유한하고 30 이하**(스크롤 3화면 이내), 슬롯당 항목이 **0~3개**, 마감이 **고정**이어서 슬롯이 늘어나지 않을 것. 최소 폭: **모바일** — 슬롯을 세로로 나열하고 격자를 쓰지 않는 형태에 한해.
> - **무너지는 조건**: 슬롯당 항목이 4개를 넘으면 슬롯 경계가 시각적으로 무너져 그냥 목록이 된다. 미배정 패널이 스트립보다 길어지면 축이 뒤집혀 있는 것이므로 `PT-01`이 맞다. 슬롯이 무한(마감 없음)이면 스크롤 끝이 없어진다.
> - **대안 패턴**: `PT-01`(행동 촉구가 목적), `PT-03`(단계 소유가 목적).
> - **근거**: 이식(ref-03 격자 밖 패널 + ref-02 2층 반전) + 이 프로젝트의 미실측. **A단계 검증 필요.**

**이 프로젝트 숫자 대입**:

| PT-04 성립 조건 | 우리 값 | 판정 |
|---|---|---|
| 슬롯 총수 유한 · **30 이하** | 12주 × 2일 = **24슬롯** (주말만). 12주 그룹 행 | ✅ |
| 슬롯당 항목 **0~3** | 확정 20~30건 ÷ 24슬롯 ≈ **0.8~1.25건/슬롯** | ✅ 여유 |
| 마감 고정 | 예식일 고정 — 우리 제약의 핵심 | ✅ |
| 최소 폭 모바일 | 세로 나열, 격자 없음. 행 1줄 56dp | ✅ |
| **무너지는 조건 역판정** | 미배정 패널이 스트립보다 긴가? 초반(12주 전)에는 확정 0건 · 미배정 20~30건 → **패널이 스트립보다 길다** | ❌ **초반 구간 불성립** |

→ **조건부 성립.** 후반(확정이 쌓인 뒤)에는 정확히 맞고, **초반에는 PT-04 자신의 무너지는 조건에 걸린다.** 이것이 C가 도전 후보인 이유이자 가장 정직한 약점이다. 완화안: 확정 건수가 임계(예: 5건) 미만이면 스트립을 접고 패널을 먼저 보여주는 이중 모드 — 그러나 **홈이 두 얼굴을 갖는 것은 12주 동안 학습 비용을 두 번 물린다.**

## 4. D-01~D-06 위반 검토

| 제약 | 판정 | 근거 |
|---|---|---|
| **D-01** | **⚠️ 부분 위반 — 하단 패널이 유일한 방어선** | 시간 축 자체는 "언제"만 답하고 "지금 뭘"을 지목하지 않는다. 하단 패널이 그 역할을 전담하는데, **패널이 화면 밖에 있다**(스트립을 스크롤해야 도달). **완화 필수**: 패널을 스트립 아래가 아니라 **상단 고정 줄에 카운트로 승격**(`자리 없는 모임 7건 ›`)하고 탭 시 패널로 점프. 이 승격 없이는 후보 자격 소멸 |

| **D-03** | **조건부 통과** | A와 같은 방식으로 상단 고정 줄에 외부화. 시간 축에 사람이 없으므로 구조적으로 자리가 없다 |

## 5. 깨지는 조건

1. **초반 12주 지점.** 확정 0~3건이면 스트립이 거의 전부 빈 슬롯이고 하단 패널에 20~30건이 쌓인다. 홈이 "아무것도 정해지지 않았다"만 반복해 말한다.
2. **모임이 주말에만 잡히지 않을 때.** 평일 저녁 모임(회사 팀·상사 1:1)이 실제로 흔하면 슬롯 정의가 무너진다 — 주말만 그리면 평일 모임이 축에서 사라지고, 평일을 다 그리면 슬롯이 84개가 되어 PT-04 성립 조건(30 이하)을 깬다. **이것이 C의 가장 큰 미확인 가정**(PRD는 "주말마다 2~3건"만 말하고 평일 여부를 말하지 않음 → `ASSUMP` 필요).
3. **한 주말에 4건 이상이 몰리는 성수기.** PT-04의 무너지는 조건 그대로. 주말 2~3건이 평균이므로 상한에 여유가 없다.
4. **급한 모임(2주 전, 마감 몇 시간).** 시간 축에서 "이번 주말" 그룹 안에 들어가지만, 몇 시간 단위 긴박함을 날짜 그룹이 표현하지 못한다.

**벌리는 방법 제안** (B-3.5 목업 제작 시 강제):
1. **상단 고정 줄의 값 개수를 후보마다 다르게 한다** — A는 2값(D-day·미배정), B는 2값, C는 3값. 더 좋은 것은 **B에서 상단 줄을 아예 없애고 미배정을 큐의 첫 섹션(`미배정 12명 [편성]`)으로 흡수**하는 것이다. 그러면 B만 "고정 헤더가 없는 홈"이 되어 골격 공유가 깨진다. **이 변형을 B의 목업 조건으로 권고한다.**
2. **섹션 구분 방식을 다르게 한다** — A는 헤더 텍스트만, B는 큐/목록 사이에 굵은 대역 구분(층이 다르다는 것을 형태로), C는 좌측 날짜 열이 그룹 경계 역할(헤더 텍스트 없음).
3. **빈 것의 표현을 다르게 한다** — A·B는 빈 섹션이 사라지고, C는 **빈 슬롯이 남는다.** 이건 이미 후보 정의 차이라 목업에서 그대로 드러난다.

## 교차 비평 ① — P1 관점 (규모·빈도 대입, 12주 내구성 / 3초 판정)

**대입 조건**: 주 수회 × 12주 ≈ **30~60세션**, 1회 수십 초, 홈 열자마자 "할 일이 있나 없나"를 **3초 안에**.

| | 3초 판정 | 12주 반복 내구성 |
|---|---|---|
| **A** | ❌ **실패.** 판정하려면 섹션 5~6개의 괄호 숫자를 읽고 비교해야 한다. 게다가 `회신 대기 (9)`는 "9건이 있다"만 말하고 **그중 몇 건이 지금 급한지**를 안 말한다 — 판정에 스크롤이 든다 | △ 골격이 12주 내내 동일해서 **변화가 숫자로만 나타난다.** 30~60회 반복에서 "지난번과 뭐가 달라졌나"를 시각적으로 못 읽는다. 안정적이지만 무디다 |

## 교차 비평 ② — 하류 이식 관점 (DESIGN.md 토큰 · 상태 화면 수)

홈 하나가 B-4·A단계에서 만들어야 할 **상태 화면 수**를 센다. (빈 상태 / 정상 / 과밀 / 로딩 / 에러)

| | 상태 화면 수 | 내역 |
|---|---|---|
| **A** | **6** | 전체 빈(모임 0) · 정상 · 과밀(한 섹션 10줄+) · **완료 누적**(후반 전용) · 로딩 · 에러. 섹션이 6종이지만 소멸 규칙 덕에 섹션별 빈 상태는 만들 필요가 없다 |
| **B** | **8 — 가장 많다** | 큐 상태 3종(빈 / 정상 / 과밀) × 하단 상태 2종(확정 0건 / 있음) 조합에서 실질 4~5 + 로딩 + 에러 + **"다 처리해서 빔" vs "아직 시작 안 함" 구분 화면 2종**. 마지막 2종은 `references.md` 사각지대 그대로라 **근거 없이 발명해야 한다** |

**토큰 요구**: 세 후보의 요구가 다르다. A·B는 **섹션 헤더 계층 1개**만 필요하지만, B는 추가로 **층 구분 대역**(큐↔목록)이라는 요소가 하나 더 늘고, C는 **좌측 날짜 열 + 빈 슬롯 행**이라는 컴포넌트 2종이 신설된다. 컴포넌트 수로는 A(최소) < B < C.

**하류 관점 결론: C 또는 A.** C는 상태 화면이 가장 적고 빈 상태 설계 부담이 구조적으로 없다. B는 상태 화면이 가장 많고, 그중 2종은 소싱에서 근거를 못 찾은 것을 발명해야 한다 — **B는 만드는 비용이 가장 비싼 후보다.**

## 남은 트레이드오프 (억지로 합치지 않음)

두 관점의 결론이 **정면으로 갈린다.**

1. **3초 판정(P1) vs 상태 화면 비용(하류)** — B는 3초 판정을 유일하게 통과하지만 상태 화면이 8개로 가장 많고 그중 2개는 근거 없는 발명이다. C는 상태 화면이 5개로 가장 적고 빈 상태 부담이 구조적으로 없지만 3초 판정에 숫자 읽기가 낀다. **이 둘은 같은 구조에서 나온 대가다** — B가 상태가 많은 이유는 홈이 데이터에 반응해 형태를 바꾸기 때문이고, C가 적은 이유는 홈이 데이터와 무관하게 항상 같은 형태이기 때문이다. **합칠 수 없다.**
2. **12주 내구성 vs 즉시 판정** — C는 남은 주말이 줄어드는 것이 매 세션 보이지만, 바로 그 이유(주인공이 시간)로 행동 판정이 한 단계 느리다. B는 반대다.
3. **D-01 vs D-05** — B는 D-01(다음 행동 지목)을 정면 충족하고 D-05(후보일 선택 시 상대편 일정)에 기여하지 않는다. C는 정확히 반대다. **여섯 제약 중 이 둘을 홈 하나로 동시에 정면 충족하는 후보는 없다.** 이것이 축 1의 진짜 트레이드오프이고, B를 고르면 D-05는 후보일 선택 화면이 별도로 전담해야 한다.
4. **미해결 실측** — `PT-01`의 큐 과밀 임계(5줄 상한)와 `PT-03`의 섹션 상한(24행), `PT-04`의 슬롯 상한(30)은 전부 **소싱에서 안 나온 발명값**이다(`refs/axis1-home.md` 사각지대 1). 세 후보 모두 A단계에서 20건·30건 더미로 실측해야 한다.
5. **C의 미확인 가정** — "모임은 주말에 잡힌다"가 참이어야 C가 성립한다. PRD는 주말 언급만 하고 평일 모임을 부정하지 않는다. 평일 모임이 흔하면 **C는 후보 자격을 잃는다.** 목업 단계에서 사람에게 물어야 할 질문이다.

# 추천안 (B)

**후보 B(2층: 행동 큐 + 다가오는 모임)를 추천안으로 본다.** 근거는 취향이 아니라 세 가지가 겹친 것이다 — 첫째, `PT-01`의 성립 조건 네 개(15건 이상 / 상태 3~6 / 신호 2종 이상 / 모바일 폭)에 이 프로젝트 숫자를 대입하면 **네 개 전부 통과하는 유일한 후보**이고, A는 항목 수 상한에 걸치고 C는 초반 구간에서 자기 무너지는 조건에 걸린다. 둘째, 여섯 제약 중 **D-01·D-02·D-03·D-04 넷을 정면 충족**하며, 특히 실패 비용이 비가역·사회적이라고 정의된 D-01(다음 행동 지목)과 D-03(미배정 상시 노출)을 구조 자체로 만족시킨다 — A는 D-01을, C는 D-01·D-04를 완화 장치에 의존한다. 셋째, `refs/axis1-home.md`의 소싱 결론이 서로 다른 세 도메인(이슈 트래커·숙박 호스팅·할 일 관리)에서 **"행동 큐가 홈이고 나머지는 부차 뷰"로 수렴**했고, B는 그 수렴을 우리 제약(마감 고정 + 1회 수십 초 + 360px)에 맞춰 압축한 결과다. 대가는 분명하다 — 상태 화면이 8개로 가장 많고, D-05를 홈이 돕지 않아 후보일 선택 화면이 그 부담을 전담하며, `막힘` 섹션의 과밀 임계는 실측 없이 발명한 값이다.

**셋 다 살려서 B-3.5 목업 보드로 넘긴다.** A는 자도메인 사용자가 첫 화면에서 기대하는 것에 가장 가깝고(학습 비용 최저), C는 `core-problem.md §2`의 세 번째 문제(자원 경합)를 홈에서 유일하게 다루며 12주 반복 내구성이 가장 강하다. 최종 선택은 사람이 목업을 보고 한다.
