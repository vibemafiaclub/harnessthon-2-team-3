# Visual Criteria (VC) — C단계 판단 기준

스크린샷을 렌더해서 **실제로 봐야** 판정 가능한 항목만. 노드 속성 조회로 답이 나오면
그건 여기가 아니라 A단계(구조적 사실 검증)에 속한다.

## 작성 규칙

1. **5필드 고정** — 증상 / 진단 / 확인 / 수정 / 라우팅. 하나라도 비면 규칙이 아니다.
   특히 `증상`은 **스크린샷에서 눈에 보이는 것**으로 써야 한다. "세련되지 않다"는 증상이 아니라 결론이다.
2. **판별력 테스트** — "이 규칙이 반대였다면 어떤 화면 결정이 뒤집히는가"에 답할 수 없으면 삭제한다.
   답할 수 없는 줄은 감상문이고, 하네스는 감상문으로 아무것도 고치지 못한다.
3. **라우팅 선결** — 판정 시점에 즉흥으로 정하지 않는다. 규칙마다 미리 `국소` / `방향` / `에스컬레이션` 중 하나를 박아둔다.
4. **근거 태그** — 실측(심사평·실제 작업 기록)인지 지어낸 것인지 구분한다. 근거 없는 규칙은 사후 대조 검증에서 걸러진다.
5. **ID는 재사용하지 않는다** — 규칙을 삭제해도 번호는 비워둔다. 과거 리포트의 `[VC-07]`이 다른 뜻이 되면 로그가 오염된다.

## 렌더 요건 (판정 전에 갖출 것)

**드라이런에서 확인됨** — 결함이 실재하는데도 렌더 배율 때문에 안 보여서 합격으로 넘어갈 수 있다.
전체 화면 1장만 보고 판정하지 않는다.

1. **전체 1장** — 위계·여백 리듬·색온도용. 화면 폭 그대로.
2. **밀집 영역 크롭 3배 이상** — 표·리스트·캡션처럼 작은 텍스트가 반복되는 영역. 타이포 관련 판정(`VC-02` 등)은 이 크롭 없이는 하지 않는다.
3. **결함 없음 ≠ 안 보임** — 안 보이면 더 크게 렌더해서 다시 본다. 배율을 올려도 안 보이면 그때 합격이다.

## 판정 리포트 형식 (하네스가 지킬 것)

C단계 판정은 반드시 규칙 ID를 인용한다. ID 없는 지적은 리포트에 쓰지 않는다.

```
[VC-03] 불합격 — 사이드바만 cool gray, 본문 카드는 warm cream. 라우팅: 국소
[VC-01] 합격
[VC-05] 판정 불가 — 빈 상태 화면이 렌더되지 않음
```

"판정 불가"를 합격으로 처리하지 않는다. 볼 수 없으면 볼 수 있게 만든 뒤 다시 본다.

## VC-01 — 색온도가 두 방향으로 갈림

- **증상**: 스크린샷 안에서 어떤 뉴트럴은 푸른 기, 어떤 뉴트럴은 노란 기를 띤다. 특히 헤더/사이드바와 본문 카드 사이에서 자주 갈린다.
- **진단**: 뉴트럴의 hue 방향이 섞이면 개별 색이 다 예뻐도 화면이 "한 벌"로 안 보인다. 서로 다른 출처에서 붙여넣은 인상이 되고, 이게 여러 화면에 걸치면 전체가 무너진다.
- **확인**: 배경 계열 면적 3곳 이상(캔버스 / 사이드바 / 헤더셀 / 카드)의 픽셀을 스크린샷에서 뽑아 **hue 각도를 계산한다.** 흰색·검정처럼 채도 0인 면은 방향이 없으므로 판정에서 제외한다. 남은 면들의 hue가 두 무리로 갈라지면 불합격. 저채도 뉴트럴은 눈으로 거의 구분되지 않으므로 **육안 비교를 1차 수단으로 쓰지 않는다** — 드라이런에서 34° vs 216°(warm/cool 정반대)조차 전체 화면 육안으로는 놓쳤다.
- **수정**: brief.md의 bg/border 토큰 전부를 warm·cool 중 한쪽으로 재바인딩한다. 개별 노드를 손대지 않고 토큰에서 고친다.
- **라우팅**: 국소 — 토큰 교체로 해결되므로 B단계로 돌아가지 않는다.
- **근거**: 청첩장모임 스케줄러 실측 — "색온도를 warm 한 방향으로 고정하면 스크린 8장이 자동으로 한 벌로 보인다"

## VC-02 — 표 안에서 세리프가 무너짐

- **증상**: 고밀도 표/리스트의 셀 텍스트가 세리프인데, 작은 크기에서 획 대비가 뭉개지고 행이 서로 붙어 보인다.
- **진단**: 세리프는 큰 크기·긴 호흡에서 인상을 만들지만, 작은 크기로 촘촘히 반복되면 가독성 손실만 남고 인상은 전달되지 않는다. 무드를 위해 넣은 요소가 정확히 그 무드를 망친다.
- **확인**: 표 영역을 **3배 이상 크롭**해서 셀 텍스트의 획 대비와 세리프 유무를 본다(전체 화면 배율에서는 폰트 교체 자체가 안 보일 수 있다). 그 다음 100% 배율에서 한 행을 실제로 읽어, 옆 행으로 눈이 새면 불합격.
- **수정**: 본문·표는 산세리프로 되돌리고, 세리프는 워드마크·대형 숫자 같은 **면적이 큰 단일 요소**로만 좁힌다.
- **라우팅**: 국소
- **근거**: 청첩장모임 스케줄러 실측 — 비주얼 무드 축에서 전면 세리프 후보가 탈락한 사유
