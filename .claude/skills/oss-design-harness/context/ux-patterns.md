# UX Patterns (PT) — 0·B단계 참조

## 이 문서를 쓰는 법

B단계는 후보를 만들기 전에 **독립 축**을 먼저 나눈다. 이 문서는 그 두 곳에 쓰인다.

1. **축 식별** — `core-problem.md`의 문제 구조를 읽고, 그 구조를 가르는 패턴이 여러 개인 지점이 곧 축이다.
2. **후보 생성** — 축마다 여기 등록된 패턴을 후보 시드로 쓴다. 여기 없는 패턴을 후보로 올려도 되지만,
   그때는 이 문서에 새 PT를 추가하고 같은 스키마로 기록한다.

## 작성 규칙

1. **5필드 고정** — 푸는 문제 / 형태 / 성립 조건 / 무너지는 조건 / 대안 패턴.
2. **성립 조건에 숫자를 넣는다** — "항목이 많을 때"가 아니라 "행 3~8 × 열 3~8". 숫자가 없으면
   하네스가 어떤 상황에도 그 패턴을 고를 수 있게 되어, 패턴 목록이 아니라 장식이 된다.
3. **무너지는 조건이 없는 패턴은 등록하지 않는다** — 모든 상황에서 좋은 패턴은 없다.
   이 필드가 비어 있으면 그 패턴을 충분히 안 써봤다는 뜻이다.
4. **대안 패턴 상호 참조** — 같은 문제를 푸는 패턴끼리 서로를 가리키게 한다. 이게 B단계의 후보 집합이 된다.
5. **근거 태그** — 실제로 만들어봤는지, 남의 화면에서 봤는지, 추측인지 구분한다.

## B단계 리포트 형식 (하네스가 지킬 것)

`decisions.md`의 후보 표에 PT ID를 인용한다. ID 없는 후보는 어디서 왔는지 추적되지 않는다.

```
| 후보 | 설명 | 비교 근거 | 선택 |
| B. 가용성 매트릭스 [PT-02] | 행=사람, 열=후보일 | ... | ✅ |
```

## PT-01 — 행동 큐 (Action Queue)

- **푸는 문제**: 서로 다른 상태의 항목이 다수 동시에 흐르는데, 사용자가 "지금 무엇을 해야 하는지" 스스로 계산해야 하는 상황. 조회 실패가 아니라 **행동 누락**이 실패 모드일 때.
- **형태**: 홈의 기본 뷰가 달력도 목록도 아닌, "당신의 행동을 기다리는 것"만 모은 단일 리스트. 각 줄은 *원인*(왜 떴는가)과 *다음 행동*(무엇을 누르면 되는가)을 함께 담는다.
- **성립 조건**: 동시 진행 항목 15건 이상 / 상태 종류 3~6 / 행동 신호의 출처가 2종 이상(마감·무응답·충돌 등)으로 흩어져 있을 것.
- **무너지는 조건**: 항목이 10건 이하면 전체 목록을 그냥 보는 게 낫다(큐가 목록의 부분집합이 되어 화면만 하나 늘어난다). 신호 종류가 1종이면 그냥 정렬이면 된다. 큐가 항상 비어 있거나 항상 20줄이면 둘 다 실패다.
- **대안 패턴**: `PT-03`(상태 보드 — 상태 소유가 목적이고 행동 촉구는 부차적일 때), 단순 마감순 정렬 목록.
- **근거**: 청첩장모임 스케줄러 실측 — 수십 건의 조율이 서로 다른 상태로 동시에 흐르는데 상태 소유 주체가 없는 구조

## PT-02 — 가용성 매트릭스 (행=사람, 열=선택지)

- **푸는 문제**: 여러 사람의 응답을 **교차 비교**해야 결정이 나는 상황. 그리고 **무응답 자체가 중요한 정보**일 때.
- **형태**: 행에 사람, 열에 선택지(날짜 등), 셀에 3~4값 상태. 열 하단에 집계 행을 붙여 결정을 즉시 내리게 한다. 무응답은 값이 아니라 **빈 셀**로 두어 시각적으로 튀게 한다.
- **성립 조건**: 행 3~8 × 열 3~8 (한 화면에 스크롤 없이 들어오는 크기). 셀 상태가 4값 이하. 데스크톱 폭.
- **무너지는 조건**: 행이나 열이 10을 넘으면 스크롤이 생겨 교차 비교라는 유일한 장점이 소멸한다. 모바일에서는 성립하지 않는다. 응답률이 100%에 가까우면 빈 셀 신호가 무의미해져 단순 목록이 낫다.
- **대안 패턴**: 날짜별 리스트 + 참석자 뱃지(교차 비교 포기, 모바일 가능), 캘린더 히트 오버레이(개인별 식별 포기, 기간이 길 때).
- **근거**: 청첩장모임 스케줄러 실측 — 일정 조율 축에서 채택된 패턴. 후보 3~6개 × 인원 3~6명이 한 화면에 들어가고, 무응답이 빈 셀로 시각적으로 튄 것이 채택 사유

## 축 후보 목록 (AX)

B단계에서 반복적으로 등장하는 독립 축. 프로젝트마다 다시 뽑되, 여기 있는 것부터 검토한다.
축은 **서로 독립**이어야 한다 — 한 축의 선택이 다른 축의 선택을 강제하면 둘은 같은 축이다.

| ID | 축 | 양 끝 | 무엇이 이 축을 여는가 |

| AX-01 | 비주얼 무드 | 장식적 ↔ 기능적 | 도메인의 정서적 맥락이 있는가 |
| AX-02 | 정보 밀도 / 주 폼팩터 | 고밀도 데스크톱 ↔ 저밀도 모바일 | 역할별 작업량이 비대칭인가 |
